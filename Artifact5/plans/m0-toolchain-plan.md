# M0 toolchain plan: VS Code + X2ModBuildCommon, hello-world mod

Approved by Kc on 2026-11-09 (Session 4, on the laptop), with the
decisions below. This covers M0's toolchain part only. The guardrail
checks that remain (PC-only rows) and loading the mod in the game happen
on the PC.

## Goal
- On the laptop: the hello-world mod compiles with the chosen toolchain.
- On the PC (later): it loads and writes one `X2TC` line to Launch.log
  when the main menu opens. That line is SPEC.md's M0 check.

## Decisions (Kc)
1. Mod and package name: `X2TacticalCoop`.
2. Log prefix: `X2TC`.
3. Builds Kc runs through the build task may write their normal output
   into the SDK and the game (CLAUDE.md updated by Kc).
4. Laptop game root: `Artifact5\local\fake-game\XCom2-WarOfTheChosen`
   (gitignored), since the laptop has no game.
5. Listener: `ScreenClass = none` with a `UIShell` cast, so it fires on
   both `UIShell` and `UIFinalShell` and logs which one it saw.
6. X2ModBuildCommon is committed in `mod/.scripts/X2ModBuildCommon/`
   with its LICENSE (MIT); its version is recorded in LOG.md.
7. The missing `Development\Src` on the laptop is not assumed to be a
   problem: build first, and suggest Steam's "Verify integrity" only if
   the build fails on missing classes.

## Toolchain: VS Code + X2ModBuildCommon
Chosen over ModBuddy because:
- nothing from the SDK's project template ends up in the public repo,
- it builds from a terminal with plain-text output,
- errors point at our own files,
- it can include the Community Highlander later (`IncludeSrc`).

X2ModBuildCommon: github.com/X2CommunityCore/X2ModBuildCommon, MIT,
"Copyright (c) 2021 X2CommunityCore". Latest release v1.2.1 (the version
the README pins). Notes from reading `build_common.ps1` on `main` (10
commits after v1.2.1, so details may differ in the release):
- Mod folder: `<workspace>\<ModName>\`, project file
  `<ModName>\<ModName>.x2proj`. Only the first `PropertyGroup` is read
  (`Name` → Title, `Description`, `SteamPublishID`). No file lists are
  checked. The `.XCOM_sln` isn't read.
- `<ModName>.XComMod` is generated by the build.
- Script packages are the folders under `<ModName>\Src\`.
- A `Localization` folder seems to be required (the build lists its files
  with errors set to stop).
- Every build mirrors the SDK's `Development\SrcOrig` into
  `Development\Src` (robocopy /MIR), compiles with the SDK's
  `Binaries\Win64\XComGame.com make`, stages in the SDK's
  `XComGame\Mods\<ModName>`, then mirrors that into
  `<gameroot>\XComGame\Mods\<ModName>`. It checks only that the game root
  exists.
- Success prints `*** SUCCESS! (<time>) ***` and `X2TacticalCoop ready
  to run.`

Changes from the plan shown in chat:
- No `.XCOM_sln`. The build script doesn't read it, and writing one needs
  a ModBuddy project-type GUID I'd have to guess. Add one later if
  ModBuddy is ever needed.
- No `mod/.gitignore`: `Artifact5/.gitignore` already ignores
  `BuildCache/` and `*.u`.
- Added the `Localization` placeholder, because the build seems to need
  that folder.
- No `X2DownloadableContentInfo` class. Guess: screen listeners in a
  mod's script package are picked up without one. The PC test will show.
- ~~No Config files~~ **Corrected after the first build (Kc approved,
  Session 4):** without config, the compiler built only the base
  packages and skipped the mod's (LOG.md, Session 4). Added
  `Config/XComEditor.ini` (`[ModPackages]`, `+ModPackages=X2TacticalCoop`:
  tells `make -mods` to compile the package) and `Config/XComEngine.ini`
  (`[Engine.ScriptPackages]`, `+NonNativePackages=X2TacticalCoop`:
  guessed to make the game load it). Both mirror what ModBuddy's
  DefaultMod template declares.

Also, outside `mod/`: `local\fake-game\XCom2-WarOfTheChosen\README.txt`,
so the fake game root exists (the build checks it with `Test-Path`).
Never committed.

## The listener
`X2TC_MainMenuListener extends UIScreenListener`, `ScreenClass = none`.
`OnInit` returns unless `UIShell(Screen) != none`, then logs once per
menu init with the tag `X2TC`. It relies on
`XComGame\Classes\UIScreenListener.uc` (L16–19) and
`XComGame\Classes\UIFinalShell.uc` (extends `UIShell`, L11).
